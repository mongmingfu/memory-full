# memory_full

一个「多角色长期记忆认知引擎」。插在聊天客户端（SillyTavern 等）和 LLM 之间，
把无状态、全知全能的大模型，变成**有边界、有视角、有记忆**的独立角色。

## 它解决什么

普通角色扮演 AI 的通病：

- **串台**：A 角色记得 B 角色才经历的事
- **全知**：角色知道它没听到、没看到的
- **错记**：AI 说的话被记到别人头上
- **忘不掉**：一次 OOC 被永久写进记忆，角色从此锁死
- **无时间感**：不知道"现在是剧里的第几天"

这个引擎给每个角色一套**认知边界**：谁知道什么、谁不该知道、
谁记得什么、谁此刻在哪 —— 每一步都要答得出「凭什么它知道」。

## 核心机制

- **认知边界**：events / event_visibility / memories / beliefs 四层分离
- **延迟一拍**：reroll 掉的回复永不落库，只留被采纳的那版
- **说话人识别**：三通道（明确对象 / 呼语位置 / 上一轮沿用），记忆不记错人
- **剧情时间轴**：角色知道现在是剧里的哪一天
- **场景位置**：谁在哪、谁不在场，不能凭空出现
- **衰减 + 合并**：重要记忆保留，闲聊自然淡出

## 为什么不是"再做一个记忆层"

市面上已经有很多"AI 记忆"方案。但它们和这个引擎在解**不同的问题**：

- **通用记忆层**（跨会话记忆、用户偏好）回答的是：*"用户上次说过什么？"*
- **这个引擎**回答的是：*"这个角色应该知道什么、不应该知道什么、记得什么、此刻在哪里？"*

区别不在"记得多不多"，在**"知道不知道"**。

一个全能大模型可以同时是所有人 —— 它不属于任何一个角色。这个引擎做的事，
是把"全知"切成"有边界的第一人称视角"，让每个角色只看见属于自己的那部分世界。

## 真实踩过的坑

下面四件事都是**生产环境真出过的事故**（脱敏后）。它们不是设计目标的宣传，
是引擎为什么长成现在这样。

### 1 · 说话人飘：对 A 说话，AI 演 B

**现象**：用户输入 `"角色A，角色C，你俩跟着你妈妈去吗？"`（点两个人）→ AI 演的是第三人。

**根因**：引擎的说话人识别在"多人被点名"时保守不猜 → 落到兜底链末端 → 兜底到
"卡里最早那个角色"。这本身不是错，但落点不理想。

**修法**：识别链改成**三通道**（明确对象 / 呼语位置 / 上一轮沿用），每条通道判据
松紧不同、走不同候选集（严判据走全集、松判据走活跃集）。不猜时打 WARNING，
不再静默落兜底。

### 2 · 窗口空了，LLM 凭空编了一整套

**现象**：抽取器从一条对话里抽出整套事件、角色、记忆 —— 但那套东西在原始对话里
一个字都没有。

**根因**：客户端把 7000 多字的写作要求当成一条 user 消息塞进窗口开头。抽取器
"第一条就超预算 → break" → prompt 里**一条对话都没进去** → LLM 只能靠想象填。

**修法**：超长单条**按剩余预算截断**而不是直接放弃；空 prompt 时**绝不调 LLM**，
直接返回 None 走规则回退。

### 3 · 删了角色，它又自己回来了

**现象**：用户物理删除一个角色 → 下一轮对话，它又出现在库里。

**根因**：引擎有"延迟一拍"机制 —— 一轮对话不是立刻落库，而是先暂存到
`conversation_meta`，下一轮请求到达时才真正写入。**删除角色时没清暂存** →
下一轮请求触发落库 → 已删角色被写回。

**修法**：所有删除操作必须同清 `conversation_meta` 的 `pending_*` 键。
这条现在是硬规程。

### 4 · 一次 OOC，被钉成永久信念

**现象**：AI 在戏里出戏说教（"这段不是戏……我不把它当成她的记忆"）→ 用户回
"我是让你认错" → 引擎把"AI 拒绝认错"本身记成了永久信念 → 每一轮都注入 →
角色越走越硬，回不到戏里。

**根因**：抽取层不区分"剧情内的叙述"和"角色站在戏外的评论"，写侧也无过滤。

**修法**：两处同时打补丁 —— 注入侧加【留在戏内】条款；写侧加**戏外元话语过滤**
（19 个标记词，命中即丢弃，不进记忆 / 信念 / 知识）。

## 一句话

**猜错的代价不是报错，是以后所有下游都把它当真。**

所以这个引擎里所有兜底机制都遵循同一条原则：

> **宁可漏记，不要错记。**

## 卡里要写什么

引擎靠**文本标记**识别卡 / 角色 / 场景。装完引擎后，按下面几项配置，否则引擎认不出：

### 开场白（或世界书常驻）里写三行

```
【卡名】你的卡名
【user】名字1，名字2
【演员】角色甲、角色乙、角色丙
```

- **【卡名】** —— 必须。引擎靠它认这张卡。不写 → 说话人飘
- **【user】** —— 必须。告诉引擎哪个名字是玩家，不是角色
- **【演员】** —— 推荐。让引擎知道卡里有哪些角色（写在开场白，别写进卡规则文本）

### AI 的状态栏里写两行（引擎自动抓）

AI 回复里出现下列标记行时，引擎会抓取当作**场景状态**：

```
📍 位置：某处
🎭 状态：正在做什么
```

- 这两行由 AI 每轮自然写出，引擎读取
- 不在场的人不能凭空出现 —— 位置靠这两行判断

### 世界书规则文本的位置

- 放 **↑Char** 或 **↑AT**（system 里）
- **别放 [AI] 插入深度 @D** —— 会被当 AI 输出落库、污染记忆

### 其余配置

身份、性格、外貌、别名 —— 在控制台手填：
- 控制台 `http://<IP>:8088/`
- 配置页 `http://<IP>:8088/settings`

## 部署

    git clone <这个仓库>
    cd memory-full-repo
    pip install pyyaml  # 仅 YAML 配置需要；纯 JSON 配置可零依赖
    cp config.yaml.example config.yaml
    # 编辑 config.yaml，填 api_key
    python3 memory_full.py init
    python3 memory_full.py serve --port 8088

然后把聊天客户端的 API 指向 http://<你的IP>:8088/v1
